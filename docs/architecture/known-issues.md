# Known Issues

Every issue recorded in the Fermitools architecture docs, collected in one
place for triage and organized by package. Each package's
`src/<pkg>/doc/architecture/` docs remain the authoritative source: they
give the context, the code locations and the reasoning behind each entry.
This file is a compiled index of them.

*Compiled 2026-10-22 from the `doc-updates` branches (each package doc's
`last_reviewed_commit` gives the code version it describes), plus a section
for the umbrella repository. Nothing here has been fixed yet.*

## How to read this

- **IDs** (`<pkg>-N`, `ST-N` for the umbrella) are stable handles for
  triage discussions and issue trackers. Within a package they are numbered
  in severity order.
- **Severity**
  - **High**: wrong scientific results, a tool or entry point unusable in
    its default or common configuration, a crash in normal use, or expired
    data affecting current dates.
  - **Medium**: a failure or wrong result in a non-default but plausible
    path, silent data loss, a misleading exit status, tests that hide
    regressions, or install and packaging defects.
  - **Low**: latent bugs not reachable today, dead or stale code shipped,
    cosmetic problems, and drift in docs or help text.
- **Evidence**
  - `runtime`: reproduced in an installed Fermitools environment.
  - `code`: established by reading the code.
  - `inferred`: likely from reading the code, but not confirmed.
- **Where** paths are relative to the package directory `src/<pkg>/`,
  except in the umbrella section, where they are relative to the repository
  root.
- An issue that spans packages is filed under the package where the fix
  belongs, and mentioned with its ID in the other package's entry.

When an issue is fixed, remove its row here and its entry in the package
doc in the same change.
